# Clerk session handoff uses verified full navigation

Clerk authentication and Only2Bali authorization intentionally remain separate: Clerk proves the external identity, while the server-only `o2b_session` selects the local account and role. Production logs showed the bridge being called but a client-side transition subsequently reusing a navigation tree whose auth check had run before the bridge cookie existed, leaving the header on “Sign in” and sometimes returning the account route to login. After a successful bridge, the completion page now resolves `/api/auth/session` with caching disabled and performs a full same-origin document navigation only when that session contains a user. This makes the cookie, server guards, and navigation control observe one committed identity; requested destinations are constrained to the active locale to prevent an authentication open redirect.
